# @fiscalia/api

The backend: [Hono](https://hono.dev) on Node, Postgres through [Drizzle](https://orm.drizzle.team), and [Better Auth](https://better-auth.com) for sign-in and organizations. See [docs/architecture.md](../../docs/architecture.md) for the reasoning.

## Running it

```sh
docker compose up -d     # from the repo root; Postgres on localhost:5432
pnpm db:migrate
pnpm dev                 # http://localhost:3000/v1
```

Every setting has a development default; copy `.env.example` to `.env` to change them. In production `BETTER_AUTH_SECRET` is required.

## Layout

```
src/app.ts             The HTTP app: middleware and routes, all under /v1
src/auth.ts            Better Auth config (email and password, organizations)
src/middleware.ts      Session loading, requireUser, requireOrganization
src/routes/            Route modules, defined with @hono/zod-openapi
src/sync/              Commands, the workspace and the change feed
src/db/schema/         Drizzle tables
drizzle/               SQL migrations generated by drizzle-kit
```

## Endpoints

- `GET /v1/health`: API and database status.
- `/v1/auth/*`: Better Auth (sign-up, sign-in, sessions, `organization/create`, `organization/set-active`…).
- `GET /v1/me`: the signed-in user and their memberships.
- `GET /v1/organization`: the active organization and the user's role in it.
- `GET /v1/workspace`: everything the app keeps for the active organization, with a cursor.
- `GET /v1/sync?since=<cursor>`: records that changed after the cursor, paged with `hasMore`.
- `POST /v1/commands`: create, update and delete commands, applied in one transaction.
- `/v1/contacts`: CRUD over clients and suppliers for the public API.
- `GET /v1/openapi.json`: the OpenAPI document.

## Sync

The web app downloads the workspace at boot, applies its changes optimistically and sends them as commands, then follows the change feed. Every write goes through `applyCommands` in `src/sync/write.ts`: it takes a per-organization lock, validates each command and logs it in `change_log`, whose `seq` is the cursor. Deletes leave a tombstone (`deleted_at`) so the feed can report them. A collection is synced once its entity is in `syncedEntitySchema` (`packages/contracts`); so far that's clients and suppliers.

To point the web app at the API, set `VITE_API_URL=http://localhost:3000` in `apps/web/.env.local`. Without a signed-in session it falls back to the sample data.

## Tenancy

Users belong to organizations through `membership` (role `owner`, `admin` or `member`). The session holds the active organization. Tenant routes use `requireOrganization`, which checks the membership and sets `organizationId` on the context; every query on tenant data must filter by it.

## Database changes

1. Edit the tables in `src/db/schema/`.
2. `pnpm db:generate --name <what_changed>` writes a SQL migration to `drizzle/`. Review it by hand.
3. `pnpm db:migrate` applies it.

CI fails if the migrations are out of date with the schema.

## Tests

Integration tests run against a real Postgres: the `fiscalia_test` database on the compose server, or `TEST_DATABASE_URL`. The database is wiped and migrated at the start of each run.
